# .claude/ — the Claude Code layer

This folder is what Claude Code itself loads. **`settings.json` is the enforcement**; everything else is instructions.

| Path | What it is |
|---|---|
| `settings.json` | Hooks wiring (which `orgnauts-hook` subcommand runs on SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, SubagentStop, Stop, PreCompact) and the static `permissions.deny` rules. Tracked. |
| `settings.local.json` | Deny rules for *your* preprod and production aliases. Written by `orgnauts-human sync`. Gitignored. |
| `agents/conductor.md` | The main-thread router. Started by `orgnauts-human start`. Its `tools:` line names the eleven specialists it may spawn. |
| `agents/a0-… a9-….md` | One specialist per file: system prompt, `model`, `effort`, `tools` allowlist, `disallowedTools`, `maxTurns`, preloaded `skills`. `sync` rewrites the model/effort lines and a1's tracker tools. |
| `commands/*.md` | The slash commands: `/ticket`, `/status`, `/approve`, `/reject`, `/hold`, `/resume`, `/feedback`, `/autonomy`, `/help`. Human-only ones are recorded by the prompt-router hook. |
| `skills/orgnauts-core-rules/` | P1 to P12. Preloaded into every agent. |
| `skills/orgnauts-*/` | Job methods: evidence contract, plan grounding, repro data first, bulk test authoring, deploy brief, escalation format. |
| `skills/std-*/` | Salesforce standards: Apex conventions, trigger framework and order of execution, flow standards, naming rules, comment conventions. |
| `skills/lessons-<agent>/` | Human-approved lessons, regenerated by `orgnauts-human learn`. Do not edit by hand. |
| `skills/<prefix>-comment-conventions/`, `<prefix>-naming-rules/` | Your org's conventions, generated by `orgnauts-human conventions build`. Gitignored. |
| `rules/*.md` | Path-scoped rules applied when an agent edits Apex, flows, metadata, UI specs or the vault. |
| `agent-memory/<agent>/MEMORY.md` | The agent's own unverified notes. Quarantined, audited by the coach. Gitignored. |

Hooks run the **installed** toolkit (`~/.orgnauts/bin/orgnauts-hook`), not the repository, so agents can never edit the code that judges them. After a toolkit change: `npm run install:toolkit`.

The matching documentation: [docs/AGENTS.md](../docs/AGENTS.md) (who does what) and [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md) §4 (every hook).
